# omo-tps-plus

[English](README.md)

OMO는 에이전트 실행이 끝날 때마다 TPS 한 줄을 띄웁니다. 이 확장은 그 줄을 그대로 두고, 마지막 응답이 시작된 로컬 시각을 덧붙입니다.

```
TPS 52.3 tok/s. Cache hit 98.1%, 12.4s. Last reply 14:32:05
```

프롬프트 캐시가 식었는지 판단할 때 씁니다. 캐시 수명(Anthropic 기본 5분)은 요청할 때마다 다시 시작되므로, 지금 시각과 `Last reply`를 비교하면 됩니다.

## 설치

```powershell
.\install.ps1
```

```sh
sh install.sh
```

스크립트는 `extension/tps.js`를 `~/.omo/agent/extensions/tps.js`(또는 `OMO_CODING_AGENT_DIR`가 가리키는 폴더)에 덮어씁니다. OMO가 생성한 연결 파일이나 이전 omo-tps-plus 사본만 교체하고, 다른 파일이면 거부합니다. 실행 중인 세션에서는 `/reload`를 입력하세요.

## 제거

`~/.omo/agent/extensions/tps.js`를 지웁니다. 다음 시작 때 OMO가 기본 연결 파일을 다시 씁니다.

## 업데이트를 따라가는 방식

TPS 수치는 여전히 senpi에 들어 있는 `tps` 확장이 계산합니다. 래퍼는 실행 중인 senpi 패키지에서 그 파일을 불러오므로, senpi를 업데이트하면 이 저장소를 다시 설치하지 않아도 새 버전이 반영됩니다. 래퍼가 하는 일은 실행이 끝날 때 그 확장이 띄우는 알림 끝에 `. Last reply HH:MM:SS`를 붙이는 것뿐입니다.

OMO는 `extensions/tps.js`가 `// Generated by` 문구로 시작할 때만 그 파일을 다시 쓰므로, 업데이트해도 래퍼는 그대로 남습니다.

## 한계

- `Last reply`는 마지막 응답이 스트리밍을 시작한 시각으로, 요청을 보낸 시각보다 1~2초 늦습니다.
- senpi 업데이트로 `tps` 파일이 옮겨지거나 없어지면 TPS 줄이 사라지고, 세션을 시작할 때 없는 경로를 알려주는 경고가 뜹니다. 제거하면 기본 TPS 줄로 돌아갑니다.

## 개발

```sh
bun test
bun qa/tui-qa.mjs --cwd <dir> --steps qa/steps/turn.json --out .omo/evidence/live
```

QA 스크립트는 실제 OMO를 150x45 터미널에서 띄우고, 프롬프트 하나를 보낸 뒤 화면을 `.ansi`, `.txt`, `.png`로 저장합니다. Chrome과 xterm.js CDN 접속이 필요합니다.
