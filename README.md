# omo-tps-plus

[한국어](README.ko.md)

After each agent run, OMO posts one TPS line. This extension keeps that line and adds the local time the run's last reply started and when the prompt cache is expected to expire:

```
TPS 52.3 tok/s. Cache hit 98.1%, 12.4s. 14:32:05 (~15:32)
```

The cache lifetime restarts with every request. It comes from senpi's own per-model TTL (`resolvePromptCacheTtlSeconds`): 1 hour on a Claude subscription, 5 minutes on Anthropic API keys. When senpi knows no TTL for the model, only the time is shown.

While the session stays open, the footer status line counts that lifetime down and shows when it has run out:

```
🔥 52m    the cache is warm; minutes left, rounded up
🧊        the cache has expired
```

The count restarts with every reply and is cleared when you switch models. Nothing is shown until the first reply after a session starts or reloads, or when senpi knows no TTL for the model.

## Install

One line, no clone needed. Windows (PowerShell 5.1):

```powershell
irm https://raw.githubusercontent.com/yjacket/omo-tps-plus/master/install.ps1 | iex
```

Linux, macOS:

```sh
curl -fsSL https://raw.githubusercontent.com/yjacket/omo-tps-plus/master/install.sh | sh
```

The script downloads `extension/tps.js` from this repository's `master` branch over `~/.omo/agent/extensions/tps.js` (or the folder named by `OMO_CODING_AGENT_DIR`). The file is fully downloaded before it replaces the installed one. It replaces only OMO's generated shim or an earlier omo-tps-plus copy and refuses any other file. Run from a clone (`.\install.ps1` or `sh install.sh`), it copies the local file instead. Type `/reload` in running sessions.

On Windows use the PowerShell line: Git Bash's curl may fail with certificate error 60 because it does not read the Windows certificate store.

## Uninstall

Delete `~/.omo/agent/extensions/tps.js`. OMO writes its stock shim back on the next start.

## How it stays current

The TPS numbers still come from senpi's own `tps` extension. The wrapper loads that file from the running senpi package, so senpi updates reach the line without reinstalling this repo. The wrapper only appends the time and the cache expiry to the notice that extension posts when a run ends, and keeps its own footer status.

OMO rewrites `extensions/tps.js` only while the file starts with its `// Generated by` banner, so updates leave the wrapper in place.

## Limits

- The time is when the last assistant reply started streaming, a second or two after its request was sent; the expiry is rounded down to the minute.
- The expiry assumes the main conversation's TTL. A Claude subscription past its usage limits drops to 5 minutes, which senpi cannot see.
- The footer status only follows the clock. It cannot see a keep-alive ping that refreshed the cache while the session was idle (senpi's `promptCache.keepAlive`, omo-keepwarm).
- If a senpi update moves or removes its `tps` file, the line disappears and a warning naming the missing path appears at session start. Uninstall to get the stock line back.

## Development

```sh
bun test
bun qa/tui-qa.mjs --cwd <dir> --steps qa/steps/turn.json --out .omo/evidence/live
```

The QA script runs the real OMO in a 150x45 terminal, sends one prompt, and saves the screen as `.ansi`, `.txt` and `.png`. It needs Chrome and network access to the xterm.js CDN.
